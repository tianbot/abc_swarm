# 控制参数核对、首轮调参与 ORCA 路线

## 动态调参并非全部有效

| 节点 | 控制方法 | 当前调参方式 |
| --- | --- | --- |
| 原 tianbot_mini_tf.py | 距离/角度 PID | tf_pid 动态回调实际更新 PID |
| 原 leader_follower.py | 前置点反馈控制 | 有 tf_pid 界面，但更新 PID 的两行被注释；主控制使用 k_1/k_2，不能通过该界面调节 |
| 原 rmtt_tf.py | 三方向 PID | 仅导入 Server，没有创建动态服务 |
| 新 pid_tracker.py | 距离/角度 PID | tf_pid 动态回调有效；通常命名为 mini_2_tracker、mini_3_tracker |
| 新 leader_follower_tracker.py | 前置点反馈+前车速度前馈 | k_x/k_y 启动时读取，不是完整 PID，也尚未提供动态服务 |
| point_stabilization.py | 距离与航向比例控制 | 本轮新增 point_control 动态服务，调整 k_distance/k_heading |
| preset_path_tracker.py | Pure Pursuit | 主要调整前视距离、速度和容差；不是 PID，启动时读取 |

旧课程文件和 config/tf_pid.cfg 均保留原内容。不能因为原文件导入了 dynamic_reconfigure，就断言参数界面与实际控制律接通。

## PID 对照中的实际问题

旧的新 PID 对照实现构造 PID 时写有另一组增益，但 tf_pid 动态服务器初始化后会用配置默认覆盖它们。默认实际是线速度与角速度 Kp=1、Ki=Kd=0。现在把构造值与这组实际默认值对齐，避免读代码时误以为积分已经打开；私有 ROS 参数和动态回调仍可设置其他增益。

另外，原“角度较小时”的分支把线速度再乘 0.5，导致即使上限 0.15 m/s，直行也可能被压到 0.075 m/s。本轮移除这个额外半速，仅保留小角度误差的转向抑制。接近目标、输出死区及限幅仍在，不保证任何距离下都恒速 0.15。

不在没有实际阶跃/跟踪数据时盲加 I、D。底盘已有速度控制，当前外环以动捕位置为反馈；应先记录位置误差、实际 odom、下发速度及时间延迟，再判断积分能否消除稳态偏差、微分是否会放大噪声。

## 点镇定首轮候选增益

| 参数 | 原值 | 本轮候选 |
| --- | --- | --- |
| k_distance | 0.6 | 0.9 |
| k_heading | 1.5 | 2.0 |
| max_linear | 0.15 m/s | 不变 |
| max_angular | 0.5 rad/s | 不变 |
| 位置/航向容差 | 0.04 m / 0.08 rad | 不变 |

候选同时写入配置、节点与共享计算的默认值。动态参数描述是 config/point_control.cfg，**没有修改旧 tf_pid.cfg**。参数服务位于 /abc_swarm_demo；启动时从目标 YAML 的私有参数读取，之后动态修改才即时生效。控制周期使用一份完整参数快照，动态修改不改变冻结目标、速度上限或 completed 状态。

该调整依据是离线比较，**不是实车系统辨识或完成的实车整定**。可复现：

```bash
python3 tests/point_gain_sweep.py
```

比较 9 组距离/航向增益，每组 6 个起点，分别在理想模型、假定 0.15 s 一阶响应+0.1 s 延迟，以及再加入位置 ±0.002 m/航向 ±0.005 rad 噪声的模型下运行，共 18 次。噪声使用固定种子。到达后继续模拟 1 秒零指令，检查滞后带来的最终误差。模型参数未从 Mini 实测辨识。

- 原 0.6/1.5：平均到达时间 9.067 s，最慢 15.950 s。
- 候选 0.9/2.0：平均 8.300 s，最慢 15.150 s；18 次都完成，最坏最终位置误差约 0.0381 m、航向误差约 0.0706 rad。
- 平均时间约缩短 8.5%，只代表以上人工模型。1.2/2.0 更快一些，但继续加增益的收益变小，先选中间候选用于后续现场验证。

读取动态参数的可选命令（节点运行时）：

```bash
rosrun dynamic_reconfigure dynparam get /abc_swarm_demo
```

它不是启动前必做步骤。默认值已调整，重新启动实验即可加载；新动态接口方便后续由助手或 GUI 在已授权的实验中逐项整定。动态修改只影响本次进程；验收后把参数保存回 YAML，才能下次复现。

本轮只读核对了现场参数，没有写入实车运行参数、发布速度或重启设备。ROS 参数残留不代表节点仍在运行，应结合服务/节点存活判断。

## ORCA 是否好实现

有现成的 [RVO2 上游实现](https://github.com/snape/RVO2)，不必从零重写线性规划。它接受各机器人状态、期望速度及静态障碍，逐步计算避让速度。三车动捕下已有统一定位和集中式实验组合，接入条件较好；但“跑通库”与“真车可靠避障”是不同的验收阶段。

Mini 是差速底盘，不能直接把二维全向避让速度拆成 linear.x 和 angular.z，也不能简单裁剪后继续声称满足 ORCA 的避碰条件。应参考 [ORCA 的差速约束工作](https://gamma-web.iacs.umd.edu/ORCA-DD/)，处理控制参考点、有效包络和运动学可执行性。

建议下一个独立动捕实验按以下步骤实施：

1. 固定 RVO2 依赖版本及接口，先用合成状态验证两车对向、交叉和三车换位；保持旧跟随/点镇定入口不变。
2. 明确每台车的碰撞半径/外形、安全余量、邻车速度来源（odom 或滤波动捕估计）、时间戳、更新周期和最大速度/转向能力。
3. 将目标控制与避障解耦：目标产生期望运动，ORCA 计算允许的避让运动，再经过验证过的差速适配输出 v/omega。对速度裁剪、急转向和执行延迟单独验证，不继承理想模型保证。
4. 首轮只处理车与车；加入静态障碍必须有显式障碍几何输入，只有动捕不能自动知道墙和桌子的位置。
5. 单独检查初始重叠、目标冲突、对称僵持、动捕失效与停止；再由用户做低速实车测试。接口与参数稳定后才登记 AI 能力表。

以上为调参阶段的设计记录。随后已按 issue #7 在动捕点镇定中接入 ORCA，见 [实现及验收范围](orca.md)；没有承诺未测的实车避碰性能。

## 本轮验证

53 项本地测试通过，冻结 main 的 48 个原资源兼容检查通过。安装环境中的点镇定闭环实际调用动态服务，验证修改生效、完成后修改不重启运动；PID 对照回归验证直线输出达到 0.15 而非 0.075。私有日志分别为 `/tmp/abc_swarm_point_ros_e0sz8va2` 和 `/tmp/abc_swarm_path_ros_0ky74k4r`。

CMake 本轮仅增加新 point_control.cfg 的生成，旧 cfg/课程清单与例外规则不变；AI 点镇定交付的组合哈希同步覆盖新动态描述文件。没有增加 ORCA 依赖或声称已支持避障。新参数仍需实车验收。
